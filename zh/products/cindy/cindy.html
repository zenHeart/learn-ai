Cindy 上手：装好并跑通第一个任务 ​

一句话结论： Cindy 是一个开源的桌面加手机 AI 智能体应用（口号 “Consider it done. 想到，就能做到。”）。 它不替你换掉 Claude Code 或 Codex，而是把这几个 agent 引擎放进同一个界面，再让同一份任务、记忆和技能跟着你跨电脑、跨手机走。 本页带你从零装上它，10 分钟内跑通第一个任务，并说清哪些数据留在本机、哪些会发出去。

写给谁、先决条件与非目标 ​

  • 写给谁：会写前端代码、用过命令行，已经在用或准备用 Claude Code、Codex 这类编码 agent 的人。你没接触过 Cindy，也没听过 harness、device link 这些词，没关系，本页第一次出现时会解释。
  • 先决条件：一台 macOS、Windows 或 Linux 电脑；一个模型来源（已有的订阅、自己的 API key、本地模型，或登录后用 Cindy 官方模型服务，四选一）。手机是可选的。
  • 非目标：
    • 不教 Claude Code、Codex、Pi 本身怎么用。Cindy 只是把它们装进来，用法请看 Claude、Codex、Pi。
    • 不教自建后端。仓库 README 写明「服务端不在本仓库」，客户端默认连接官方云服务。
    • 不教从源码构建和读源码，那是源码解读的事。
    • 不覆盖团队版与企业版。官网首页写的是「即将上线」和「联系我们」，个人用不上。

学完你能做什么 ​

  1. 用三句话说清 Cindy 解决什么问题，以及它不替你做什么。
  2. 在电脑上装好 Cindy，在「登录」和「跳过登录」之间做出自己的选择，并知道两者的区别。
  3. 用你已有的订阅或 API key 跑通第一个任务，并用脚本核对它到底改了哪些文件。
  4. 把第二台电脑和手机连起来，在手机上查看任务，必要时接手电脑桌面。
  5. 用记忆、Skill、伙伴、自动化和聊天渠道，把重复的事交出去。
  6. 说出默认有哪些统计数据会发出去、怎么关，以及哪一项关不掉。

准备一个模型来源 ​

Cindy 客户端免费，但模型调用要有人付费。官方给出四类来源，选你已经有的一类：

来源怎么接适合谁
已有的订阅登录授权。中国大陆版首页列的是 Claude、ChatGPT、SuperGrok、Kimi Code、MiniMax、GitHub Copilot已经在为某个订阅付钱的人
自己的 API key 或 Coding Plan在设置里添加供应商并填入 key。两家首页都写可用 Key 接入其他受支持的 Coding Plan，中国大陆版点名了智谱、阿里云有 API 账号、想自己控制用量的人
本地模型连接 Ollama、llama.cpp、LM Studio 等本机运行时。官方标注为 Beta，表现取决于模型与硬件不想让内容离开电脑的人
Cindy 官方模型服务登录后按需使用，按量或包月付费不想自己配置的人

官网首页写明：「我们鼓励你使用自己的订阅和 key。」另有一句要记住：「Pi 是 Harness，无需另买一份订阅。」

核心概念 ​

术语表 ​

术语一句话解释为什么需要
harness真正去执行任务的那个 agent 引擎，例如 Claude Code。Codex 和 Pi 也是 harness模型只会推理和生成文字；读文件、跑命令、决定下一步做什么，是 harness 在组织
任务（session）你和 agent 的一段持续对话，带工作目录和完整历史。官方界面里叫「任务」换屏幕、换 harness 时，接续的对象就是它
一轮（turn）你发一句话，到 agent 干完活停下，算一轮权限确认、排队、插话都按轮管理
模型供应商（model provider）模型从哪里来，即上面那四类来源harness 和模型是两层选择，同一个 harness 可以换不同模型
Device Link让登录同一账号的电脑和手机互相找到、互相控制的通道电脑上的任务要在手机上看和接手，先得连得上
记忆（memory）agent 存下来、以后还能读到的偏好和知识否则每次开新任务都要从头交代
Skill一份写给 agent 看的操作说明，放在带 SKILL.md 的文件夹里把「怎么做某类事」固定下来，不用每次复述
插件（plugin）打包成 .cindy 文件、能加界面和新工具的扩展Skill 只教方法，插件能接入外部服务
MCP一种给模型接工具的通用协议把你自己的系统接进 agent
伙伴（companion，英文界面里叫 Buddies）有名字、职责、记忆和技能的长期搭档代码审阅、资料研究这类反复出现的工作，交给固定的角色
自动化（automation）按时间或循环自动跑的任务周报、巡检这类重复的事不必每次手动发起
聊天渠道（channel）Slack、Telegram、飞书这类你本来就在用的聊天工具在聊天里 @ 一句就能交办
远程桌面在手机上看到并操作电脑真实画面的功能聊天搞不定、需要亲手点软件的时候用
Orca（协同）一个 Lead 任务带着多个 Worker 任务分工干活一个 agent 不够用时，让不同 harness 各干一段

harness：干活的是它，不是 Cindy ​

官网常见问题的原话：「Claude Code、Codex、Pi 是负责组织执行的 Agent Harness；模型负责推理与生成。」 README 对三者的描述：Claude Code 是「熟悉的 Claude Code 工作方式，接上 Cindy 的界面与工具」；Codex 是「Codex 的代码工作流，与其他 Agent 在同一个产品里配合」； Pi「轻量、开源、可扩展，原生支持多种模型供应商」。桌面安装包自带这三个引擎的可执行文件（README 的 apps/*-bin 一行），不用另外安装。 官网同时提醒：可用组合取决于所接入的服务、授权与模型能力，不是任意 harness 配任意模型都行。

任务与 Device Link：你的电脑当服务器 ​

  • README 说「任务仍留在 Cindy」：不管底下换哪个引擎，任务的历史、工作目录和设置由 Cindy 保管。所以你能在另一台设备打开同一个任务，也能中途换 harness。
  • README 的「你的电脑，变身免费的服务器」指你自己的电脑：任务在电脑上执行，项目文件留在那台电脑。手机和另一台电脑只是「看和说」的入口。仓库里 device-link 的说明写明，手机版是纯控制端，本地没有 agent、会话和数据库。
  • 远程访问不等于整盘同步。 README 原文：「项目文件仍在原电脑上，可远程访问不等于整盘自动同步。」

记忆、Skill、插件、MCP：四层可复用的东西 ​

层是什么官方怎么说
记忆偏好、项目背景等零散知识，由 Cindy 按工作目录管理「把偏好和知识留在记忆中」
Skill一份操作说明，可复用、可分享，载体是技能目录里的 SKILL.md「把有效的方法写成可复用、可分享的 Skill」
插件带界面和新工具的安装包，包格式 .cindy「从 SkillHub 发现 Skill 和插件」
MCP接入自建系统和内部工具的协议「通过 Skill、插件和 MCP，继续连接自己的工具」

伙伴、自动化、渠道、远程桌面、Orca ​

  • 伙伴：README 写的是「给她角色、指令、Skill 和日常工作：代码审阅、资料研究、项目跟进，都可以有专门的搭档」。
  • 自动化：把重复的事设成定时或循环任务。
  • 渠道：英文 README 写的是 Slack 和 Telegram，中文 README 写的是「Slack、飞书等聊天渠道」。
  • 远程桌面：README 的原话是「内置远程桌面，需要时直接打开应用、输入和操作自己的电脑」。它需要单独授权。
  • Orca（协同）：源码文档的定义是「一个 Lead session 负责拆任务、派活、验收与汇总，多个 Worker session 负责并行或串行执行」，并且「Worker 是完整会话，不是一次性 subagent」。官网首页那个「规划、并行执行、独立复核」的三步示例，注明了是「用法示意」。

它是怎么工作的 ​

先记住一句话：Cindy 自己不直接调模型干活，干活的是 harness。 Cindy 做的是三件事：给你一个统一界面，管好每个 harness 的进程和会话，再把任务、文件和模型访问延伸到你的其他设备。 源码里引擎是三个固定值 claude-code、codex、pi，外加一种由插件提供的 acp（packages/maker-core/src/types/common.ts 第 8 到 16 行）。

带着这个问题看下一张图：一句任务从手机或电脑发出后，要经过哪几层才到达 harness？哪些数据始终留在你的电脑上，哪些会发到 Cindy 的服务或模型供应商？

图的依据： 分层、设备角色与数据流向，来自仓库 README.zh-CN.md 的「连接与数据如何处理」「隐私与遥测」两节，以及 packages/device-link/README.md 的「角色与拓扑」；心跳只在已登录的云端会话期间发送，对照 heartbeatService.ts L6–L10，源码均为提交 6fdec7fb；使用统计的默认值与关闭方式对照隐私政策（截至 2026-11-24）。图中保留了四个区域的对象、四条云端连线的方向，以及哪些东西留在本机的标注；省略了服务端的内部模块，因为后端不在开源仓库里。本图不对官方中继是否会读取数据下结论，也不标价格与额度。

图里最该看清的是两个方向的边界。

第一个边界在界面和 harness 之间。 三个 harness 各说各的话，Cindy 给每个 harness 写了一个适配器，把它们翻译成同一种事件流（文本、工具调用、Diff、确认请求、完成、错误）。 所以任务记录、Diff 和确认卡在换引擎后长得一样。细节到源码解读里看。

第二个边界在你的设备和云端之间。 下表按数据逐项列出，是你决定「登录还是跳过登录」的依据：

数据留在本机吗什么时候会发出去
项目文件是，在执行任务的那台电脑开启远程访问或云伙伴同步时，相关消息、文件、元数据会经 Cindy 服务传输
对话记录与 agent 调用历史是同上；选官方模型服务时，请求还会经过官方网关
你发给模型的提示词和上下文否每次请求都发给你选的模型供应商
API key 与登录凭据是，加密存储订阅登录的令牌刷新可能由官方服务处理
设备信息与在线心跳否仅登录模式，约 60 秒一次
使用统计否默认开启，可以关

依据是隐私政策第 I 节第 3 条：「对话记录、Agent调用历史、工作目录下的文件及API Key通常存储在您的本地设备上。」 以及第 II 节第 2 条：用自备 key 或订阅时，输入「可能从本地设备直接发送至您选择的模型供应商」；用官方网关时，内容会经过网关再转给模型。完整清单见下文「安全与隐私要点」。

还有两种图上没画的形态：任务可以通过 SSH 在另一台机器上跑，或者 Agent 在别的电脑上跑、文件留在你这台。它们属于进阶用法，本页不展开。

安装 ​

关于本页的步骤：作者没有在本机安装并运行 Cindy。步骤依据四处官方材料核对：仓库的中文 README、官网（下载页、定价页、隐私政策）、仓库里的界面文案（apps/desktop/src/renderer/i18n/locales/zh-CN/common.json）和产品规则文档（docs/product-rules/）。 带「」的文字是界面或文档里的原文。你手上的版本可能改过按钮位置，以界面为准。

macOS 与 Windows ​

  1. 做什么：打开你选定的下载页。macOS 按芯片选 Apple 芯片 或 Intel 芯片，下载 .dmg；Windows 下载 Windows x64 的 .exe。
  2. 做什么：像安装其他桌面软件一样完成安装，然后打开 Cindy。

Linux ​

两个下载页的说法不一致，按你的版本选：

版本现状怎么装
国际版下载页提供 Linux x64 与 ARM64页面给出的命令是 curl -fsSL https://hotfix.cindy.app/cindy/install-omarchy.sh | bash，在终端执行
中国大陆版下载页写「正在准备发行包与安装说明」「准备中」到 GitHub Releases 找文件名以 -linux-x64-cn.deb 或 -linux-arm64-cn.deb 结尾的包。v0.1.144 的 Release 里确实有这两个文件

仓库的 Linux 安装指南 列了四条路线：

环境安装方式更新方式
Ubuntu 22.04 / 24.04官方 .deb，经 apt应用内下载，明确重启后生效，需要 polkit 授权
Arch Linux、Omarchy（Hyprland）x86_64一条命令的用户级安装应用内下载，明确重启后切换版本
其他 glibc 桌面同一个用户级安装脚本，需有兼容的运行库官方注明「不表示每个发行版都测试过」
pacman、AUR 或其他第三方包用那个包管理器安装不要再用应用内更新

该指南不支持 Alpine（musl）和以 root 身份运行的桌面会话。

手机 ​

在 App Store 搜 Cindy，或在下载页获取 Android APK，然后登录和电脑相同的账号。手机端的功能是「查看、追问和接管电脑上正在运行的 Cindy 任务」，所以电脑端要先装好。

第一次打开：登录还是跳过登录 ​

登录页有两个选择。这是你做的第一个重要决定：

登录（README 里叫「远程托管」）跳过登录（本地模式）
界面文字各种登录方式跳过登录（Skip Sign-In），下方写着「无需 Cindy 账号，数据保存在本机。云模型、跨设备与市场服务不可用。」
需要的账号Cindy 云端账号不需要
账号状态显示你的账号未登录（Not signed in）
能用本机 agent 任务、Cindy 官方模型服务、跨设备访问、远程桌面、云伙伴同步、SkillHub 与插件市场本机 agent 任务
不能用无官方模型服务、跨设备、市场服务
在线心跳有，约 60 秒一次没有
使用统计（TapDB）默认上报，可关不上报

README 特别澄清了一件事：「跳过登录」不是连接本地服务端。 它指的是不登录 Cindy 账号就能用本机 agent；客户端仍然默认连接官方云服务的地址，只是依赖服务端的能力在这个状态下用不了。

我的情况用什么
想用手机、连多台电脑，或者不想自己配模型登录
只在一台电脑上用，自带 API key 或本地模型，不想让设备保持在线跳过登录
想先看看它长什么样跳过登录，之后可以再登录

登录或跳过之后，新电脑会出现一个开始引导窗口，只列和你有关的步骤，每一步都能跳过。 其中「连接模型」一页讲两种方式，官方写明可以一起用：Cindy AI（官方模型服务，登录后自带）和用你自己的套餐。页面会列出本机检测到的已登录订阅，其余进「其他供应商与 API Key」。以后想再看，入口是「设置 → 通用 → 开始引导」。

10 分钟跑通第一件事 ​

目标很小：让 Cindy 在一个空文件夹里新建一个文件，然后你自己核对它只做了这一件事。 第一次别拿重要项目练手。 agent 能在你的电脑上执行命令，先在无关紧要的文件夹里建立信任。

第 0 步：建练手文件夹，拍一张快照 ​

打开终端，新建一个空文件夹：

bash
mkdir cindy-trial && cd cindy-trial

把下面这个脚本存成 snapshot-diff.mts，放在这个文件夹外面的任意位置（例如你的主目录）。它在交给 Cindy 之前记录每个文件的哈希，任务跑完后告诉你哪些文件新增、修改、删除了。

ts
// snapshot-diff.mts —— 交给 Cindy 之前先给文件夹拍个快照，任务跑完再比对。
// 用法：node snapshot-diff.mts snap <文件夹>
//       node snapshot-diff.mts diff <文件夹>
import { createHash } from 'node:crypto';
import { promises as fs } from 'node:fs';
import os from 'node:os';
import path from 'node:path';

// 依赖和构建产物里文件太多，比对它们只会得到上千行噪音。
const IGNORED = new Set(['node_modules', '.git', 'dist']);

/** 相对路径 → 文件内容的 SHA-256。 */
type Snapshot = Record<string, string>;

async function walk(dir: string, root: string, out: Snapshot): Promise<void> {
  const entries = await fs.readdir(dir, { withFileTypes: true });
  for (const entry of entries) {
    if (IGNORED.has(entry.name)) continue;
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) {
      await walk(full, root, out);
    } else if (entry.isFile()) {
      const bytes = await fs.readFile(full);
      out[path.relative(root, full)] = createHash('sha256').update(bytes).digest('hex');
    }
  }
}

async function main(): Promise<void> {
  const [command, target] = process.argv.slice(2);
  if (!target || (command !== 'snap' && command !== 'diff')) {
    console.error('用法: node snapshot-diff.mts <snap|diff> <文件夹>');
    process.exitCode = 2;
    return;
  }
  const root = path.resolve(target);
  // 快照按文件夹分开存，放在系统临时目录，不污染你的项目。
  const store = path.join(
    os.tmpdir(),
    `cindy-snapshot-${createHash('sha256').update(root).digest('hex').slice(0, 12)}.json`,
  );
  try {
    const stat = await fs.stat(root);
    if (!stat.isDirectory()) throw new Error(`${target} 不是文件夹`);
    const now: Snapshot = {};
    await walk(root, root, now);
    if (command === 'snap') {
      await fs.writeFile(store, JSON.stringify(now, null, 2), 'utf8');
      console.log(`已记录 ${Object.keys(now).length} 个文件`);
      return;
    }
    const before = JSON.parse(await fs.readFile(store, 'utf8')) as Snapshot;
    for (const file of Object.keys(now).sort()) {
      if (!(file in before)) console.log(`新增  ${file}`);
      else if (before[file] !== now[file]) console.log(`修改  ${file}`);
    }
    for (const file of Object.keys(before).sort()) {
      if (!(file in now)) console.log(`删除  ${file}`);
    }
  } catch (error) {
    const err = error as NodeJS.ErrnoException;
    // 「还没拍快照就 diff」是最常见的错，给一句能照做的提示。
    console.error(
      err.code === 'ENOENT' && err.path === store
        ? `找不到快照，先运行: node snapshot-diff.mts snap ${target}`
        : `出错: ${err.message}`,
    );
    process.exitCode = 1;
  }
}

void main();

拍快照（把路径换成你存脚本的位置）：

bash
node <脚本所在目录>/snapshot-diff.mts snap .

空文件夹预期会看到 已记录 0 个文件。

为什么用 .mts：这是 Node 直接运行 TypeScript 的写法，不需要装任何依赖。Node 22.18 及以后默认支持；22.6 到 22.17 需要加参数 --experimental-strip-types。 这段脚本我在 Node v24.16.0 上实际跑过六种情况（正常、未拍快照、缺参数、文件夹不存在、传了文件、有改动），输出和退出码都符合预期。 文件名必须是 .mts：我试过 .ts，Node 会把它当成 CommonJS 而报 Cannot use import statement outside a module。

第 1 步：新建任务，选练手文件夹 ​

  1. 做什么：在 Cindy 里新建任务，工作目录选刚才的 cindy-trial 文件夹。如果看到 worktree 相关的勾选项，第一次保持关闭。

第 3 步：发第一句任务 ​

把权限保持在你看到的默认档位，第一次逐条看确认。然后发送：

text
在当前文件夹里新建一个 hello.txt，内容只写一行：Hello Cindy。
不要创建或修改其他任何文件。做完告诉我你改了什么。

会看到什么：任务开始运行，界面陆续显示 agent 的工具调用和结果；需要你点头的操作会停下来，出现确认卡。确认卡上写明它要做什么，看清楚再允许。 为什么这样写任务：范围小、结果可验证、明确禁止多余动作。这是检验任何 agent 是否听话的最省事的办法。

关于权限，源码里的档位有六个内部值：ask、default、acceptEdits、plan、auto、bypassPermissions。其中 bypassPermissions 就是 Full access，从别的档位切进去必须显式确认；客户端不认识的值一律按最安全的 ask 处理。 这六个值在界面上的名称分两套，随执行任务的 agent 而定。下表抄自界面文案里 newChat.permissionSelector.modes 下的 label（zh-CN/common.json L14447-L14521）：

内部值内置的 Claude Code、Codex、Pi插件引擎（经 ACP 接入的外部 agent）
ask默认权限逐项确认
default选择器里没有这一项默认
acceptEdits允许编辑，只有 Claude Code 有自动接受编辑
plan选择器里没有这一项只规划
auto自动审批自动
bypassPermissions完全访问全部允许

右列只在任务由插件引擎执行时出现，选择器此时只提供该引擎声明的档位（PermissionSelector.tsx L74-L78）。ACP 是 Agent Client Protocol，一种让外部 agent 接入客户端的协议。「计划模式」是界面里另一个开关，不在这两套名称里（zh-CN/common.json L20101）。

第 4 步：看它改了哪些文件 ​

分两路核对，一路看 agent 的自述，一路看事实。

  • 看界面：任务过程里 Cindy 会给出本轮改动的 Diff（源码里对应 turn_diff 事件，定义是「provider 对本轮工作区变更的累计 unified diff」），也可以在右侧栏的审查面板看 git 数据。
  • 看事实：回到终端运行 node <脚本所在目录>/snapshot-diff.mts diff .。任务按约束执行的话，会看到一行 新增 hello.txt。再用 cat hello.txt 确认内容只有一行 Hello Cindy。

只有第二路算数。 如果多出一个文件，或者别的文件被改了，说明任务没有按约束执行。这时先别放进重要项目，回头检查权限档位和任务描述。 任务没问题想继续，直接在同一个任务里发下一句，agent 记得上一轮的上下文。想核对它是否记得，可以问：「你刚才创建了哪个文件？」

日常用法 ​

换 harness 接着干 ​

目标：同一个任务先用一个引擎规划，再换另一个引擎执行，不用复制粘贴上下文。

  1. 做什么：在任务里打开模型选择器，换一个 harness 并选好模型。会看到什么：界面立刻显示你的新选择，但底下的引擎还没换。
  2. 做什么：照常发下一条消息。会看到什么：这条消息发出时才真正切换，对话里会出现一条切换边界，可以展开看交接全文。
  3. 为什么：Cindy 先登记「你想换」的意图，等下一条消息时再执行一次切换，这样反复改选不花钱。

这里必须讲明白一件事。 README 原文：「任务仍留在 Cindy，跨 Harness 时会交接或重建引擎上下文，并非把不同引擎的内部状态原样搬过去。」拆开说：

会带过去的不会原样搬过去的
Cindy 写给新引擎的交接文本（之前做了什么、现在到哪一步）旧引擎「脑子里」的东西：隐藏的推理过程、它自己的会话缓存
任务的历史记录、工作目录、你在 Cindy 里设的权限两个引擎各自原生会话里的内部状态
Cindy 管理的记忆和 Skill

源码的注释把流程写得很具体：构造交接文本，关掉旧引擎的会话，在数据库里记下切换，插入一条边界记录，再在新引擎里重建会话。 切回原来的 harness 时，Cindy 会尽量恢复它原来的原生会话，只补上离开期间的进展。所以实践上的建议是：关键约束写进任务消息或记忆，别只放在某个引擎的会话里。 两个限制：通过 SSH 跑在别的机器上的会话不支持切换；协同里的 Lead 和 Worker、审阅任务、已归档任务，也不支持由 agent 自己做这种完整切换。

连接第二台电脑和手机，并用远程桌面 ​

目标：人离开电脑后，还能在手机或另一台电脑上接着处理同一个任务。

前提是 README 的三句话：「电脑在线、设备登录同一账号，并开启相应权限。模型共享需要允许对应供应商被远程调用，远程桌面也有独立的授权与系统权限。」

  1. 做什么：第二台电脑装 Cindy，登录同一个账号，再在这台电脑的远程连接设置里打开「允许同账号设备控制本机」。 会看到什么：另一台设备刷新后能看到这台电脑。被控时，被控的电脑上会出现「桌面正在被远程控制」的提示。
  2. 做什么：手机装 Cindy，登录同一个账号，在设备列表里切换设备，打开任务，继续对话。 为什么：任务还在原电脑上跑，手机发的是控制指令。电脑一关机，远程任务就停了。官网常见问题写明：手机「不会把离线电脑的工作自动搬到云端执行」。
  3. 想借用另一台电脑的模型：在那台电脑上允许对应供应商被远程调用。任务留在原来的电脑，只借用另一台的模型访问。

远程桌面：先在被控的电脑上打开上一步的开关，再开启远程桌面；然后手机上打开「远程桌面」，按提示完成授权，就能看到电脑的真实画面并输入操作。

手机对电脑能做的事有明确边界。仓库里 device-link 的说明写明：可远程调用的通道全集是一张默认拒绝的白名单，包括新建和关闭任务、发消息、处理确认、切换模型与权限、读取历史； 账号与密钥、被控端的全局设置、本机弹窗永远不放行。

隐私提醒：默认的 Device Link 流量可以经官方中转，也可以直连，协议里没有端到端加密字段。有一个叫 Agent-Net (Beta) 的新版连接方式，产品规则写明「端到端加密」且「默认关」，需要你在设备上手动打开。

用记忆和 Skill 固化经验 ​

记忆。最省事的做法是在对话里直接说「记住：……」。Cindy 给 agent 的记忆说明里列出的触发词包括「记住」「我希望」「别再」，以及你纠正它的时候。 记忆分四类：user（你的角色与偏好）、feedback（纠正与认可）、project（这个工作目录的进展与约束）、reference（外部系统的入口）。 记忆按工作目录划分，并且跨引擎共享，换 harness 不会丢；它和 Claude Code、Codex 各自自带的原生记忆是两套，互不相通。远程控制端只能读记忆和记忆设置，白名单里没有远程修改它们的通道。

Skill。可以从 SkillHub 安装现成的，也可以自己写：建一个文件夹，放一个 SKILL.md。Cindy 扫描时会读取文件头部的 description。 仓库的产品规则还写明，Claude Code、Codex、Pi 的技能目录由 Cindy 直接识别，不用重复安装。一个最小的 SKILL.md：

markdown
---
description: 把本仓库里的废弃 API 替换成新写法。用户提到「替换旧 API」「升级 xx」时使用
---

按下面的顺序做，每一步做完再进下一步：

1. 先用 grep 列出所有还在用旧 API 的文件，只列出来，不要改。
2. 等用户确认清单后，一次只改一个文件。
3. 每改完一个文件跑一次 `pnpm lint`，把结果贴出来。
4. 全部改完给出一份改动清单：新增、修改、删除了哪些文件。

建一个伙伴 ​

目标：给「代码审阅」这类反复出现的工作配一个固定角色，不用每次重写角色设定。

  1. 做什么：打开伙伴入口，新建伙伴，填名字、职责和工作方法，挂上记忆与 Skill。
  2. 会看到什么：伙伴有自己的默认模型，和新建任务时你选的模型互不影响。
  3. 做什么：给它安排日常工作（见下一节的自动化），或者绑定消息平台，从聊天里给它派活。
  4. 为什么：伙伴的意义在于积累。它的记忆和技能会随每次合作留下，下次接着用。

伙伴属于账号，不属于某台电脑。每个伙伴有一台主力电脑，它的 agent 只在这台上运行，工作目录、登录状态和文件都在这里；其他电脑和手机是看和说的入口。 主力电脑离线时，Cindy 会明确告诉你，并提供「在这台电脑继续」，默认不自动换电脑。云端只同步对话层（你看得到的消息和伙伴的最终回复），工具调用明细和完整运行记录留在主力电脑。 已经在用 OpenClaw 或 Hermes 的，首次引导里可以把伙伴导入。

设自动化，并接聊天渠道 ​

自动化：

  1. 做什么：打开「自动化」，新建一条，填任务内容和时间或循环规则。
  2. 会看到什么：到点后它自动开一轮任务，运行记录留在页面里。
  3. 为什么：自动化由你电脑上的 Cindy 执行，所以电脑得开着。仓库的规则写明，无人值守时遇到需要确认的操作，确认卡会等待回答或超时，你可以在通知或手机上处理。所以给自动化的任务，要么不需要确认，要么你确定到点能看手机。

聊天渠道：

  1. 做什么：在设置里的渠道设置卡，或伙伴的「消息平台」对话框里，选 Slack、Telegram 或飞书，按页面指引填机器人凭据。
  2. 会看到什么：连上之后，在聊天里 @ Cindy，它把这条消息变成一轮任务，结果回到聊天里。
  3. 为什么：这是把工作交出去最顺手的方式，但数据会经过聊天平台、Cindy 服务和你的电脑三处。

v0.1.96 的更新说明写到，中国大陆版此前看不到官方机器人和个人 Telegram、Discord、Lark 的配置，从那个版本起两个版本提供相同的入口。

用 Orca 让多个 agent 分工 ​

目标：一件大到不适合一个 agent 的事，拆给几个 harness 并行做。

  1. 做什么：在一个普通任务里打开协同开关。
  2. 做什么：新建 Worker，为它选 harness、模型、推理强度和权限，再写明它要做的事。
  3. 会看到什么：界面变成左右分栏，一边是 Lead，一边是当前关注的 Worker。每个 Worker 是一个独立任务，有自己的历史。
  4. 做什么：对 Lead 说你要什么，比如「把 README 的英文化拆成三个 Worker：正文、示例代码、术语表。」

Lead 通过一组工具指挥 Worker。源码里给 Lead 的说明列出了这些工具：get_workspace_info、create_worker、create_workers、send_to_worker、interrupt_worker、update_worker，以及几个管理 Worker 队列的工具。 Worker 做完后通过 send_to_lead 回报，Lead 会被自动唤醒，不需要反复查询。

三条边界来自仓库的协同架构文档：一个团队严格绑定一个 Lead 任务，不能跨 Lead 共享 Worker；切换关注的 Worker 是「换一个显示」，不是多个 Worker 并排；本地的 Claude Code、Codex、Pi 都可以当 Lead 或 Worker。 和子代理的区别：Worker 是完整的会话，在界面上可见、有持久历史；子代理是某个 agent 内部一次性的子任务执行者。源码里给 Lead 的提示明确要求不要把两者混用。

  • 用量额度覆盖「当前区域」官方服务的全部模型。中国大陆版列的是 DeepSeek、Kimi、GLM、Qwen；国际版列的是 GPT、Claude、Grok、Gemini 以及上述几家。
  • 每个任务花多少，实时显示在会话上。
  • 已有订阅仍按供应商的限额和规则使用。GitHub 上 v0.1.101 的更新说明提到，任务撞上 5 小时或每周用量上限时，会显示预计自动继续的时刻，可以取消。

安全与隐私要点 ​

这一节单独讲，因为它最容易在新手这里被跳过。Cindy 能执行命令、读你的文件，还默认连着官方云服务，所以要知道默认有哪些数据会出去。 先给结论：不想让设备保持在线，就用「跳过登录」；用了登录，就手动关掉「使用统计」。

默认会发出去的四类数据 ​

机制发了什么默认状态能不能关
使用统计（TapDB）设备标识、系统与应用版本、启动与回访；登录后用区域内的账号代号；参与统计的桌面设备每天选了哪个模型和模型用量。不含对话、提示词、文件和工作目录数据开能，见下一小节
在线心跳用户 ID、平台、应用版本；设备登记还包括设备名称、系统版本、CPU 型号、内存大小、是否开启远程控制、忙闲状态登录模式下开不能。隐私政策写明「无法由用户关闭」；本地模式不发送
诊断日志你手动上传的日志；另有「崩溃时自动上传」选项手动上传；自动上传默认关不传就不发。原生崩溃转储只留在本地
模型请求提示词、相关上下文、附件、工具结果用了就发发给你选的模型供应商；选官方模型服务时经过官方网关，并有内容安全检测

心跳和「使用统计」是两套独立机制。README 原文：「在线心跳与诊断日志是独立机制，不受『使用统计』开关控制。」

关掉使用统计 ​

  • 桌面端：「设置 → 关于 → 使用统计」。关闭后立即停止后续上报。
  • 移动端：「设置 → 关于这台手机 → 使用统计」（隐私政策给的路径；README 的说法是设置页的「使用统计」）。关闭后会立即解绑账号并停止 Cindy 主动触发的上报，但已经初始化的原生统计组件不能卸载，要彻底退出并重新打开应用，它才保持未初始化。

README 还主动披露了一个移动端的已知例外：企业 SSO 登录跳过了勾选协议这一步，在特定情况下迁移逻辑可能把新装用户也标记为「已同意」，于是在已配置统计且开关开着时，即使用户没明确接受隐私政策也可能开始上报。官方给的规避办法就是关掉「使用统计」。

本地模式与登录模式的差别：选「跳过登录」时，不上报使用统计、不发送在线心跳、不登记设备信息，也不维持 Device Link 的在线状态。两种模式的完整对比见上文安装一节的表。

另外四件容易忽略的事 ​

  • 文档预览会临时上传。 隐私政策写明，预览 DOCX、PPTX 这类格式会调用云端转码，文件临时上传，转换完成后即时删除。
  • 聊天渠道是第三处。 启用飞书机器人或其他消息集成后，消息、指令、文件和执行结果会经过消息平台、Cindy 服务和你的本地客户端。
  • 分享任务是本地文件。 导出的 .cshare 文件可以设密码；不设密码，拿到文件的人就能看内容。官方不保存密码，也找不回。
  • 本地模型是 Beta。 官网写明表现取决于模型、硬件和运行时。想做到内容不离开电脑，还要同时用本地模式，并且不接聊天渠道、不开远程访问。

最后一条来自官网常见问题的原话：「本地优先不等于所有数据永不离开设备。」请按自己的需求选择服务、权限与同步方式。

常见坑 ​

症状原因解决
界面显示「未登录」，手机连不上电脑用的是跳过登录的本地模式，没有 Device Link登录同一个 Cindy 账号
手机上看不到自己的电脑电脑离线，或没开「允许同账号设备控制本机」让电脑保持在线，登录同一账号，打开开关
电脑合盖后任务停了远程任务由电脑执行，手机只是入口需要任务继续时别让电脑睡眠；Cindy 不会把任务搬到云端
换了 harness 后，agent 像是忘了几个细节切换靠交接文本重建上下文，旧引擎的内部状态不过去把关键约束写进任务消息或记忆
在 Git 仓库里新建任务后，自己的目录里看不到改动可能启用了 worktree，改动在独立的工作树里到审查面板看本轮 Diff；新建任务时关闭 worktree 选项
关了「使用统计」，电脑还在定期联网那是在线心跳，另一套机制登录模式下无法关闭；介意就改用跳过登录

故障排查 ​

我的情况去哪里
不知道某个功能怎么用用 GitHub issue 里的「Usage question / 使用问题」模板提问
遇到 Bug提 GitHub issue，附上版本、平台、复现步骤和脱敏后的日志
需要日志诊断日志可以手动上传，上传前要经过隐私同意
怀疑是安全漏洞按 SECURITY.md 的流程私下报告，不要开公开 issue
想看第三方组件的许可服务条款写明入口在「菜单-设置-开源许可」

两条来自仓库使用支持文档的提醒：社区能帮忙确认可复现的问题，但不承诺为每个自定义环境做一对一排障；不要在公开 issue 或日志里放真实用户数据、访问令牌、私钥或内部地址。
