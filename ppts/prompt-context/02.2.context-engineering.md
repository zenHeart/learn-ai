# 2. Context 工程

---

# 什么是 Context Engineering？

<v-clicks>

1. **Context**：模型本轮推理时**实际看到的全部输入 Token**。

2. **Context Engineering**：围绕任务目标，选择、检索、压缩、排序和维护这些 Token，让模型看到**最小但足够的高信号信息**。

</v-clicks>

<v-click>

```
Context = System Prompt
        + Memory 注入（CLAUDE.md / `.cursor/rules/`）
        + RAG 召回内容  ← 向量检索：把相关文档找出来注入窗口
        + 对话历史
        + 工具调用结果
        + 当前 User 输入（你写的 Prompt）
```

</v-click>

<v-click>

> **本质**：Prompt 定义任务契约，Context 提供事实材料；Context Engineering 解决的是**给什么、给多少、放哪里、何时更新**。

</v-click>

---

# 为什么需要 Context Engineering？

<v-clicks>

**三个硬约束**逼着你做 Context 工程：

</v-clicks>

<v-click>

| 约束 | 含义 | 工程后果 |
|------|------|---------|
| **事实不在权重里** | 模型不知道最新代码、业务状态、实时信息 | 必须注入当前事实与证据 |
| **窗口是预算** | 容量、成本、注意力都有限 | 必须做最小有效集 |
| **位置会影响注意力** | Lost in the Middle 现象 | 关键事实要分块、排序、放到高权重位置 |

</v-click>

# 首尾定律：Attention 是位置敏感的

> 引用：[Liu et al. 2023, *Lost in the Middle*](https://arxiv.org/abs/2307.03372)

<v-clicks>

**研究发现**：文档位置直接影响模型注意力权重——

</v-clicks>

<v-click>

```
注意力权重分布：

  ▲
  │ ██                                              ██
  │ ███                                            ███
  │ ████                                          ████
  │ █████                                        █████
  │ ██████                                      ██████
  │ ████████                                  ████████
  │ █████████████                        █████████████
  └──────────────────────────────────────────────────►
       开头（高）          中间（低）         结尾（高）
```

</v-click>

<v-clicks>

- 20 文档检索答案：**第 1 位 71%** 准确率，**第 10 位 51%**（[Liu et al. 2023](https://arxiv.org/abs/2307.03372)）
- **首尾定律**：关键约束 → System Prompt（开头）；当前任务 → User Input（结尾）
- 中间内容会被"淹没"——**无关信息坚决过滤**

</v-clicks>

<v-click>

> **工程原则**：宁可短而精，不要长而散；位置即权重。

</v-click>

# 装配选型：RAG vs 长上下文 vs 全量

<v-clicks>

**按场景选择，而非"窗口越大越好"**：

</v-clicks>

<v-click>

```
你的场景？
│
├─ 答案在明确文档，接受秒级延迟
│   └─ → RAG（向量检索 + 召回注入）
│
├─ 需跨 200+ 文档推理，无明确"正确答案"
│   └─ → 长上下文（注意首尾定律）
│
├─ 代码库 < 50K Token，可全部放入
│   └─ → 全量放入（关键约束放 System / 结尾）
│
└─ 频繁交互，每次只问一小部分
    └─ → 动态切块 + 滚动窗口
```

</v-click>

<v-click>

> **窗口大 ≠ 效果好**——attention 优化与组织策略才是关键。

</v-click>

# Context 装配：检索 / 压缩 / 注入

<v-clicks>

**检索**：先找到证据源，而不是预先塞满窗口

**压缩**：摘要、裁剪、去重，只保留任务相关信号

**分级注入**：System / Memory / Tool / User 各司其职

**来源标记**：让每个关键事实可追溯、可验证

</v-clicks>

<v-click>

```python {1-4|5-6|all}
# 分级注入示例
messages = [
    {"role": "system",      "content": "你是一个 Vue3 审查助手"},
    {"role": "user",        "content": "分析这个组件的问题"},
]
# Tool Result 运行时注入（按需）
tool_results = [{"content": summarize(file_content), "source": "Login.vue"}]
```

</v-click>

<v-click>

> **实践原则**：让 AI 按需读取，而不是把所有材料预先塞进窗口。

</v-click>

# Context 实战原则：少塞、多取、可恢复

**来自 Cursor / Claude Code / Manus 的共同经验**：Context 管理不是把材料堆满，而是让 Agent 在工作中持续取证。

::left::

<div class="col-good">

### ✅ 该固定注入的

- 项目规则：`AGENTS.md` / `CLAUDE.md` / Rules
- 当前状态：cwd、git status、最近打开文件
- 任务目标：当前用户请求和验收标准

### ✅ 该运行时读取的

- 大文件、日志、网页、PDF、历史对话
- 通过 `Read` / `Grep` / `@file` / RAG 按需拉取

</div>

::right::

<div class="col-good">

### ✅ 该外部化保存的

```text
todo.md        # 当前计划
notes.md       # 关键发现
sources.json   # URL / 文件路径 / 引用来源
```

- 压缩可以丢正文，但不能丢路径、URL、证据来源
- 长任务反复更新 todo，让目标回到最近上下文
- 错误观察保留摘要，避免重复踩同一个坑

</div>

# Context 反模式：好 vs 坏

::left::

<div class="col-bad">

### ❌ 资料一把梭

```
帮我看看这段代码，它是我们项目里
的数据处理逻辑，这个项目用的是
TypeScript，我们要求严格类型，
```

- 背景 / 数据 / 约束混成一团
- AI 答非所问，假设一堆不存在条件

</div>

::right::

<div class="col-good">

### ✅ 精准外科手术

```xml
<context>
项目：nn-client-all | TS strict | Node 18

</context>

<code>

  const result = (data as any).items.map(...)
}
</code>

<question>
分析 crash 根本原因，给出类型安全
的修复方案
</question>
```

- 背景 / 代码 / 问题分块清晰
- 用 XML/Markdown 结构化标记

# Context 安全红线

<v-clicks>

**Context 不只是性能问题，更是攻击面**——四个红线必须知道：

</v-clicks>

<v-click>

| 风险 | 攻击形态 | 防御 |
|------|---------|------|
| **数据泄漏** | `.env`、密钥、内部文档被读入 Context → 模型复述/记入历史 | `.cursorignore` / `.aiignore` 黑名单 + 提交前扫描 |
| **Context 污染** | 过期文档、错误注释混入 → AI 误判 | 仓库即文档 + 定期清理 + 版本标记 |
| **Token 失控** | 盲目堆 @全目录 → 成本爆炸 + Lost in the Middle | 最小有效集原则 + 监控 Token 消耗 |
| **跨会话泄漏** | A 项目的 Context 被 B 项目摘要带过去 | 项目隔离 / 上线前敏感信息 mask |

</v-click>

<v-click>

```
✅ 三道防线：
   ① 入口拦截：.cursorignore / git-secrets / 提交前扫描
   ② 运行隔离：只注入任务所需材料，外部内容标注 source / untrusted
   ③ 出口审计：所有 Context 注入留痕，便于追溯泄漏
```

</v-click>

# 工具复用：不同工具的 Context 注入形态

<v-clicks>

**Context 注入不是手动拼字符串**——主流工具各有自己的"注入语法"：

</v-clicks>

<v-click>

| 工具 | Context 注入语法 | 自动注入源 |
|------|----------------|----------|
| **Cursor** | `@file` `@code` `@docs` `@web` `@git` | `.cursor/rules/` |
| **Claude Code** | `@path` + `Read` tool + Skill | `CLAUDE.md` + `~/.claude/CLAUDE.md` |
| **OpenCode** | `@path` + 自定义 commands | `AGENTS.md` |
| **通用 RAG** | 向量检索 → 相似度 Top-K 召回 | 知识库索引 |
| **通用 MCP**（Model Context Protocol）| 标准化协议 → 可插拔 Context 源 | MCP Server 配置 |

</v-click>

# 本章小结：Context 工程

<v-clicks>

1. **信息边界**：Context 是模型本轮真正看见的世界，没进窗口的信息等于不存在

2. **注意力预算**：精准比全面重要，最小有效集同时降低噪声、成本和 Lost in the Middle 风险

3. **动态装配**：按任务检索、压缩、排序和标注来源，把关键事实放到正确位置，并保留恢复路径

</v-clicks>
