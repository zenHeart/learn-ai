# 2. Context 工程

---

# 什么是 Context Engineering？

<v-clicks>

1. **Context**：模型本轮推理时**实际看到的全部输入 Token**。

2. **Context Engineering**：围绕任务目标，选择、检索、压缩、排序和维护这些 Token，让模型看到**最小但足够的高信号信息**。

</v-clicks>

<v-click>

```
Context = System Prompt
        + Memory 注入（CLAUDE.md / `.claude/rules/` / `.cursor/rules/`）
        + RAG 召回内容  ← 向量检索：把相关文档找出来注入窗口
        + 对话历史
        + 工具调用结果
        + 当前 User 输入（你写的 Prompt）
```

</v-click>

<v-click>

> **本质**：Prompt 定义任务契约，Context 提供事实材料；Context Engineering 解决的是**给什么、给多少、放哪里、何时更新**。

</v-click>

---

# 为什么需要 Context Engineering？


<v-click>

| 约束 | 含义 | 工程后果 |
|------|------|---------|
| **不在权重的事实** | 模型不知道最新代码、业务状态、实时信息 | 必须注入当前事实与证据 |
| **窗口限制** | 容量、成本、注意力都有限 | 必须做最小有效集 |
| **[上下文腐烂](https://www.trychroma.com/research/context-rot)** | 上下文越长，模型越不稳定地使用信息，噪声会放大退化 | 不能把“塞更多”当成“更可靠” |
| **位置会影响注意力** | Lost in the Middle 现象 | 关键事实要分块、排序、放到高权重位置 |

</v-click>

> 引用：[Liu et al. 2023, *Lost in the Middle](https://arxiv.org/abs/2307.03372) 文档位置直接影响模型注意力权重

<v-clicks>

- **首尾定律**：关键约束 → System Prompt（开头）；当前任务 → User Input（结尾）
- 中间内容会被"淹没"——**无关信息坚决过滤**

</v-clicks>

<v-click>

> **工程原则**：宁可短而精，不要长而散；位置即权重。长任务用 `/compact <focus>`，无关任务用 `/clear`。

</v-click>

# Context 实战原则

**来自 Cursor / Claude Code / Manus 的共同经验**：Context 管理不是把材料堆满，而是让 Agent 在工作中持续取证。

::left::

<div class="col-good">

### ✅ 该固定注入的

- Claude Code：`CLAUDE.md` / `.claude/rules/`
- 已有 `AGENTS.md`：在 `CLAUDE.md` 里用 `@AGENTS.md` 导入
- 当前状态：cwd、git status、最近打开文件
- 任务目标：当前用户请求和验收标准

### ✅ 该运行时读取的

- 大文件、日志、网页、PDF、历史对话
- 通过 `Read` / `Grep` / `@file` / RAG 按需拉取

</div>

::right::

<div class="col-good">

### ✅ 该外部化保存的

```text
CLAUDE.md         # 每次都要看的项目地图
.claude/rules/   # 路径级规则
.claude/skills/  # 按需加载的复杂流程
```

- 长任务反复更新计划，让目标回到最近上下文
- 错误观察保留摘要，避免重复踩同一个坑

</div>

# Claude Code 会话治理：常用上下文指令

**核心要点**：上下文窗口是预算。不要靠“记住更多”，而要在**打断、查看、压缩、清空、回滚、分叉、恢复**之间做选择。

| 指令 | 解决什么问题 | 典型使用场景 | 使用判断 |
|------|--------------|--------------|----------|
| `Esc` | **即时刹车**，停止当前响应或工具调用，保留已完成工作 | 发现它读错文件、跑偏方向、准备执行不该做的操作 | 还不需要回滚，只要马上纠偏 |
| `/btw <question>` | **旁路提问**，不写入主对话历史 | 临时问“刚才那个配置名是什么？”“前面结论是哪条？” | 只问已有上下文里的事实；不能读文件、跑命令 |
| `/compact [focus]` | **压缩历史**，把长对话替换成聚焦摘要 | 阶段性完成后继续同一任务：调研完、修完一组问题、准备下一步 | 任务没变，但历史太长；带上 focus 指令 |
| `/clear [name]` | **清空上下文**，开启干净会话；旧会话仍可恢复 | 切到无关任务；同一问题连续纠偏两次还失败 | 任务边界变了，或失败路径已经污染上下文 |
| `/rewind` 或 `Esc Esc` | **回到检查点**，恢复代码/对话，或只压缩某一段 | 试错方向错误、误改文件、想保留早期指令但丢弃后续分支 | 需要“撤回状态”或定点压缩，而不是全量 compact |
| `/branch [name]` | **分叉会话**，复制当前上下文试另一路径 | 两种实现方案都值得试；想保留原路径不被污染 | 探索替代方案，原会话必须可回去 |
| `/resume [session]` | **恢复会话**，按名称/ID/选择器接回任务 | `/clear` 或退出后回到旧任务；并行任务之间切换 | 长任务先 `/rename`，后续更容易 resume |
| `/context [all]` | **看预算**，定位哪些内容占用上下文 | 长任务开始变慢、模型遗漏早期约束、准备压缩前 | 先诊断，再决定清理还是压缩 |

<div class="governance-rule">
口诀：<strong>跑偏先 Esc，同题用 /compact，换题用 /clear，错路用 /rewind，试分支用 /branch，回任务用 /resume，临时问题用 /btw, 变长看 /context，。</strong>
</div>

<!--
演讲者备注：依据 Claude Code Sessions、Best Practices、Commands、Interactive Mode 和 Checkpointing 文档汇总。强调 /compact 适合同一任务续航，/clear 适合无关任务或失败路径污染，/btw 不进入历史且不能用工具，/rewind 是 checkpoint 级恢复或局部摘要，/branch 是尝试替代方案而不破坏原会话。

# Context 安全红线


<v-click>

| 风险 | 攻击形态 | 防御 |
|------|---------|------|
| **数据泄漏** | `.env`、密钥、内部文档被读入 Context → 模型复述/记入历史 | `.cursorignore` / `.gitignore` 黑名单 + 提交前扫描 |
| **Context 污染** | 过期文档、错误注释混入 → AI 误判 | 仓库即文档 + 定期清理 + 版本标记 |
| **Token 失控** | 盲目堆 @全目录 → 成本爆炸 + Lost in the Middle | 最小有效集原则 + 监控 Token 消耗 |

</v-click>

# 工具复用：不同工具的 Context 注入形态

<v-clicks>

**Context 注入不是手动拼字符串**——主流工具各有自己的"注入语法"：

</v-clicks>

<v-click>

| 工具 | Context 注入语法 | 自动注入源 |
|------|----------------|----------|
| **Cursor** | `@file` `@code` `@docs` `@web` `@git` | `.cursor/rules/`  |
| **Claude Code** | `@path` + Read/Grep/Bash，`/clear`、`/compact`、`/rewind`  | `CLAUDE.md` / `.claude/rules/` / Skills |
| **通用 MCP**（Model Context Protocol）| 连接内外部资源 | MCP Server 配置 |

</v-click>

# 本章小结：Context 工程

<v-clicks>

1. **信息边界**：Context 是模型本轮真正看见的世界，没进窗口的信息等于不存在, 模型无法完成任务优先考虑信息给的足不足

2. **注意力预算**：高信号、可定位、可验证的信息比“堆积资料”更重要

3. **动态装配**：按任务检索、压缩、排序和标注来源，把关键事实放到正确位置，并保留恢复路径

</v-clicks>

<!--
演讲者备注：Context 工程的核心是"给得准"。不要把它讲成资料越多越好，而要强调信息边界、注意力预算和动态装配。首尾定律是最重要的机制，安全部分要落到最小注入和可追溯来源。
