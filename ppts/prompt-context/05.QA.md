# Q1：模型变笨了，是怎么回事？

<v-clicks>

**可能原因**：

1. **模型版本漂移**：厂商更新了模型，行为可能变化
2. **Context 污染**：对话历史稀释了 System Prompt 的权重
3. **窗口截断**：Token 快满时，早期关键上下文被挤出
4. **高负载时段表现波动**：排队 / 超时增多，间接放大"变笨"的主观感知

</v-clicks>

<v-click>

**应对策略**：

| 策略 | 场景 | 做法 |
|------|------|------|
| 新开会话 | 任务切换时 | 关键约束写入 CLAUDE.md（项目规范文件），新会话自动加载 |
| 摘要压缩 | 长对话中途 | 让 AI 总结已达成的共识，清除历史重开 |
| 固定版本 | 关键任务 | 锁定模型版本，不随"latest"自动升级 |

</v-click>

# Q3：Harness 和 Vibe Coding 有什么关系？

<v-clicks>

**Vibe Coding**：依赖 Agent 能力和开发者经验来完成项目

**Harness 工程**：为 AI 建立可持续的工程环境，适合生产、团队协作

</v-clicks>

<v-click>

```
Vibe Coding：
用户："做个登录页面" → AI 全程完成 → 用户验收

Harness 工程：
用户："做个登录页面" → AI 读 CLAUDE.md → 读 BaseComponent.vue
→ 按规范生成 → CI lint + 测试 → 人类 Review / Merge
```

</v-click>

<v-click>

> **关系**：Harness 是 Vibe Coding 在团队、生产场景的工程化升级。

</v-click>

# Q4：Claude 连续改错怎么办？

::left::

<div class="col-bad">

### ❌ 不要这样做

```text
不对，再改一下。
还是不对，再看看。
你怎么又改错了？
```

- 错误路径堆进上下文
- 失败方案污染判断
- 越纠偏越像在补丁上打补丁

</div>

::right::

<div class="col-good">

### ✅ 失败恢复流程

```text
1. 连续两次纠偏失败：/clear
2. 把新学到的信息写成新 Prompt
3. 明确排除已失败方案
4. 必要时 /rewind 回检查点
5. 大范围调查交给 subagent / 新会话
```

> 新 Prompt 要包含：事实、失败路径、当前假设、最小验证命令。

</div>

# 课程总结：Prompt · Context · Harness

<v-clicks>

1. **Prompt 问得对**：**ICIO 框架**，明确任务(Instruction)、背景(Context)、输入(Input)、输出格式(Output Indicator)，同时写清验收和验证命令

2. **Context 给得准**：只给高信号、可定位、可验证的信息；用 `CLAUDE.md` 做地图，用 `.claude/rules/` 和 Skills 按需加载规则
3. **Harness 管得住**：用 Tools/MCP 取证，用 Tests/Lint/Hooks 验证，用 `/clear`、`/compact`、`/rewind` 管理长任务和失败恢复

</v-clicks>
