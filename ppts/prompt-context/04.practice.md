# 5. 实战演练

两个通用场景，一个核心原理

---

# 两个场景，一个核心问题

<v-clicks>

**场景一：写一封邮件**
→ 如何用结构化 Prompt，一次生成符合要求的邮件

**场景二：分析一个问题**
→ 如何把关键信息给得准，让 AI 真正找到根因

</v-clicks>

<v-click>

**核心问题**：同样的模型、同样的需求，**输入的质量决定输出的质量**。

</v-click>

---

# 场景一：裸 Prompt vs 装备 Prompt

<v-click>

**第一步：没有任何结构时**

```
用户：帮我写一封邮件，跟客户说项目要延期

AI 输出：
尊敬的客户：
您好！我们的项目需要延期。
给您带来不便，敬请谅解。
此致敬礼
```

→ 模糊、没有细节、没有解决方案、没有新时间线

</v-click>

---

# 场景一：装备 Prompt 的输出

**第二步：使用结构化 Prompt**

```markdown
## 角色
你是一位专业的项目经理，擅长客户沟通

## 任务
撰写一封项目延期通知邮件

## 背景
- 项目：官网改版
- 原定交付：5月15日
- 新交付：5月25日
- 延期原因：客户临时增加需求（多语言支持）
- 已完成：90%，剩余多语言测试

## 要求
- 语气专业但不卑不亢
- 先说明情况，再给出方案
- 附上新的时间表
- 不要过度道歉
```

---

# 场景一：关键实践

<v-clicks>

**1. 明确角色**
- 告诉 AI"你是谁"，它会用对应的语气和视角

**2. 结构化任务**
- 角色 / 任务 / 背景 / 要求——四要素缺一不可

**3. 提供具体数据**
- "5月15日"比"原定时间"更精准
- AI 不会自造时间线

**4. 明确约束**
- "不要过度道歉"比"写得专业一点"更可控

</v-clicks>

---

# 场景二：信息过载 vs 精准信息

**背景**：团队季度销售业绩下滑，需要分析原因

<v-click>

**错误的做法：把所有信息丢给 AI**

```
这是我们的销售数据、会议记录、客户反馈、
市场报告、竞品分析、团队周报......
请帮我分析业绩下滑的原因
```

→ AI 收到海量信息，开始"随机分析"，给出一堆泛泛而谈的建议

</v-click>

---

# 场景二：精准信息切取策略

**正确做法：外科手术式精准切取**

<v-clicks>

**Step 1：定位核心问题**
- 不是"业绩下滑"，而是"哪个产品线、哪个区域、下滑多少"
- 把大问题拆成小问题

**Step 2：切取关键数据**
- 只要最近 3 个月的核心指标对比
- 不要原始数据，要趋势和异常点

**Step 3：结构化呈现**
- 数据：具体数字、对比、趋势
- 背景：什么变了、什么没变
- 问题：你怀疑什么、已经排除什么

</v-clicks>

---

# 场景二：精准信息示例

```xml
<数据>
- Q1 销售额：500万（目标600万，达成率83%）
- 同比下降：15%
- 主要下滑产品线：企业版（下降30%）
- 区域分布：华东区下降40%，其他区域持平
</数据>

<背景>
- 华东区 Q1 更换了销售负责人
- 企业版竞品 Q1 降价 20%
- 团队人员流动率：华东区 30%，其他区域 10%
</背景>

<已排除>
- 产品质量问题（客户满意度无变化）
- 市场整体萎缩（行业报告增长10%）
</已排除>

<问题>
分析华东区企业版销售下滑的根因，
给出可执行的改进方案
</问题>
```

---

# 场景二：AI 精准输出

<v-click>

**AI 分析（直指根因）**：

```
根因分析：
华东区企业版销售下滑是多重因素叠加：

1. 人员因素（权重 60%）
   - 新负责人上任，团队磨合期
   - 30% 流失率导致客户关系断裂
   - 老客户被竞品挖走

2. 竞争因素（权重 30%）
   - 竞品降价 20%，价格优势明显
   - 企业版决策周期长，价格敏感度高

3. 产品因素（权重 10%）
   - 企业版功能与竞品趋同，差异化不足

改进方案：
1. 短期（1个月）：老客户回访，挽回流失客户
2. 中期（3个月）：竞品对标，推出差异化功能
3. 长期（6个月）：华东区团队重建，加强培训
```

→ 数据驱动、权重清晰、方案可执行

</v-click>

---

# 场景二：关键实践

<v-clicks>

**1. 把大问题拆成小问题**
- "业绩下滑" → "华东区 + 企业版 + 下降30%"

**2. 数据要具体**
- "下降30%"比"下滑明显"更精准
- AI 能基于数字做量化分析

**3. 提供已排除的线索**
- 告诉 AI"什么不是原因"，避免它重复分析

**4. 明确你要什么**
- "分析根因 + 给方案"比"帮我看看"更可控

</v-clicks>

---

# 通用原则：适用于任何场景

<v-clicks>

| 原则 | 适用场景 | 示例 |
|------|---------|------|
| **结构化输入** | 写邮件、写报告、写方案 | 角色/任务/背景/要求 |
| **精准上下文** | 分析问题、做决策 | 只给关键数据，不给全部 |
| **明确约束** | 任何 AI 输出 | "不要..."比"要..."更可控 |
| **提供示例** | 格式要求、风格要求 | 给一个"好"的例子 |

</v-clicks>

<v-click>

> **核心结论**：Prompt Engineering 不是技术专利，是**思维结构化**的能力。
> 你不需要会编程，只需要会"把问题说清楚"。

</v-click>

---

# 本章小结：实战演练


<v-clicks>

1. **场景一证明 Prompt 的价值**：目标、约束和示例越清楚，输出越接近可用结果

2. **场景二证明 Context 的价值**：精准信息比海量信息更能帮助模型定位问题

3. **通用原则**：结构化输入、最小有效上下文、明确验收标准，今天就能用于真实任务

</v-clicks>
