# 案例目的：三层协同的全流程演示

**本案例展示**：心跳需求从设计到规则沉淀的全生命周期中，Prompt × Context × Harness 如何在每个阶段协同起作用。

**三层分工**（对应前几章）：

| 层次 | 职责 | 核心机制 |
|:------:|:------:|:----------|
| **Prompt** | 任务契约 | ICIO 框架定义"做什么" |
| **Context** | 证据材料 | 现象 + 证据 + 复现步骤 |
| **Harness** | 验证闭环 | fake timers + Mock Store |

<v-click>

> **关键认知**：三层不是线性流程，而是**同时存在、相互约束**。

</v-click>

# Step 1：需求 → Prompt 任务契约

**核心要点**：不要把"做一下"丢给 AI，要先定义完成标准。

::left::

<div class="col-bad">

### ❌ 模糊需求

```text
帮我实现一个社区心跳功能。
```

- 不知道用什么接口
- 不知道上下文怎么获取
- 不知道怎样算完成

</div>

::right::

<div class="col-good">

### ✅ 可复制给 Claude Code

```text
先进入 plan mode，不要改代码。

目标：复用 batchQuery 接口实现社区心跳。
范围：只改社区心跳相关模块，不重构路由和全局 store。
参考：先读取设计文档、coding.mdc、现有 batchQuery 用法。
验收：
- 补齐单元测试
- 覆盖正常路径和竞态场景
- 输出验证命令和结果

请先给实现计划：改动文件、数据流、风险和测试方案。
```

**期望返回**：不是代码，而是计划、证据来源和验证方式。

</div>

# Step 2：Context 不是资料堆

**核心要点**：Agent 最需要的是"可定位证据"，不是完整文档。

::left::

<div class="col-good">

### ✅ 最小有效 Context

```xml
<现象>
进入社区后心跳未触发
</现象>

<证据>
- store 状态：communityItem.serverId = 7520
- 路由状态：routerStore.state.to.params.community = undefined
- 接口调用：batchQuery 尚未返回
</证据>

<复现>
首页 → 登录 → GameCard 进社区
</复现>

<已排除>
- 接口本身异常
- 路由参数错误
</已排除>
```

</div>

::right::

<div class="col-good">

### ✅ 让 Agent 按需读取

```text
先读取这些文件：
- src/composables/useCommunityHeartbeat.ts
- src/composables/communityHeartbeatContext.ts
- tests/communityHeartbeat.spec.ts

如果需要更多信息，先说明原因，
再读取最小相关文件。
```

**期望返回**：已读文件、关键事实、还缺什么证据。

</div>

# Step 3：Harness 让质量闭环

**核心要点**：不要在 AI 回答"已实现"时停下；要让它拿证据回来。

::left::

<div class="col-good">

### ✅ 先复现失败

```text
请先写一个失败测试：
- Vitest + fake timers + Mock Store
- 模拟接口先返回、路由稍后切换
- 断言心跳不会因为中间态被错误清空

测试失败后再实现修复。
修复后运行：
npm test -- communityHeartbeat
```

</div>

::right::

<div class="col-good">

### ✅ 竞态场景覆盖

```typescript
// ❌ 之前：直接设置路由，跳过竞态窗口
setRouteCommunity(7520)

// ✅ 之后：模拟路由未切换
setRouteHome()
setRouteCommunity(7520)
```

**关键差异**：模拟接口先返回、路由稍后切换的真实时序。

**期望返回**：失败测试截图/日志、修复 diff、验证命令结果。

</div>

# Step 4：规则沉淀变成团队资产

<v-clicks>

**不要只留下代码 diff，还要留下 Agent 下次能读到的规则。**

心跳案例触发的 coding.mdc 规则：

| 规则 | 触发点 |
|------|--------|
| **异步时序与上下文状态** | 接口返回但路由未切换时不能清空会话 |
| **防御性处理** | 边界 + 出口各做一次，中间层不重复 |
| **注入器模式命名** | `resolveXxx` 区别于 `getXxx` |
| **先翻库再造轮** | 用 `createEventHook` 而非手写 `Set` |

</v-clicks>

<v-click>

```text
请把这次踩坑沉淀为项目规则：
- 只写下次会再次避免错误的规则
- 放到对应路径级 rule，而不是塞进 CLAUDE.md
- 每条规则包含触发场景和正反例
```

</v-click>

# Skills 与 Rules 的工程映射

**选择原则**：

| 任务特征 | 资产类型 |
|---------|---------|
| 高频、复杂流程 | Skill |
| 编码规范、强制约束 | Rule |
| 快捷命令、即时触发 | Command |
| 一次性分析 | 直接 Prompt |

# 本章小结：实战演练

<v-clicks>

1. **三层协同**：Prompt 定契约、Context 给证据、Harness 做验证

2. **Context 精准**：最小有效证据集 > 资料堆

3. **Harness 复现**：fake timers + Mock Store 覆盖时序竞态

4. **规则沉淀**：本次失败 → 下次防护，Skills/Rules 是工程复用载体

</v-clicks>
