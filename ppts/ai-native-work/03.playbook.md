# 最小度量：怎么知道在放大

| 结果性（收益） | 过程性（健康度） |
|----------------|------------------|
| 重复劳动小时下降 | 人工介入次数 |
| 交付周期 / 返工 | Skill 复用 vs 从零 prompt |
| 可并行处理量 | 预检失败、权限误触 |

建议：自己选 **1 个结果指标 + 1 个过程指标**，按飞轮 **周复盘**。

::: tip
没有指标，飞轮第四步「迭代」会变成感觉良好。
:::

# 沉淀 Skill：四步（Evals 是门禁）

| 步 | 做什么 | 标准 |
|----|--------|------|
| **1. Find** | 公司 kit / 官方 / 社区是否已有 | 先搜再造 |
| **2. Create** | 边界、步骤、I/O | 结果导向 description、单职责 |
| **3. Evals** | 对/错例与验收 | **无验收 = 无复利** |
| **4. 打磨** | 失败写回、缩权 | 手改啰嗦稿；权限收紧 |

MCP：**先 CLI/API 跑通**，高频再包装；Skill 编排 SOP，MCP 提供原子能力。

# bugfix 证明了什么

`/bugfix` 是个 12 步状态门的状态机（`INTAKE → … → CLOSED`），不是一句 prompt：

| 门禁 | 做什么 |
|------|--------|
| **本地优先** | 复现、定位、修复、复核全在 `local`，不碰生产分支 |
| **两类互证证据** | UI + Network/日志/定向测试，缺一类不能过 `VERIFIED_LOCAL` |
| **人工确认点** | `LOCAL_READY` 后停下——「本地已修复，远程未核验」；要不要继续交付，人说了算 |
| **交付门禁** | 没有 MR + 报告 + SHA 绑定，只能说「未完全验证」，不能说「修复完成」 |

**这就是全篇反复讲的三句话，在一个真实场景里全部兑现：**  
人守关键节点 · 无验收 = 无复利 · 失败即停。

`bugfix` 内部还调用 `debug` 技能——工序叠工序，能力可组合。它是 `nn-client-all` 项目自己长出来的 Skill，不在 `@nn/ai-kit` 中心分发之列，和「按场景选用」页「个人高频事务 → 自建 Skill」是同一件事，只是长在了项目粒度。

# nn-ai：公司级可复用能力层

**@nn/ai-kit** = 工作台上的 **MCP 手脚 + Skill 工序**。

| 层 | 内容 |
|----|------|
| **你的工作台** | Claude Code / Codex / Cursor … |
| **公司层** | atlassian · gitlab · zentao · insight · jenkins · wecom |
| **工序层** | /spec · /cr · /wiki · /insight · /expense（示例）… |

安装心智：按内网 registry 安装/更新 ai-kit，验证 MCP 与 Skills 可见。  
**内网系统统一走 nn-ai，避免私接脚本以后自己都找不回来；项目自己的 Skill（如 `/bugfix`）不必等中心分发才能造。**

# 开工前最小检查

| 检查项 | 未满足时的风险 |
|--------|----------------|
| 仓库有记忆文件（含测试/验收） | Loop 无法自验 |
| 模糊任务先 Plan | 大面积返工 |
| 内网能力已接 nn-ai | 复制粘贴上下文 |
| 危险操作有门禁 | 误发布 / 误改 |
| 重复活已 Skill 化或有口令 | 无法复利 |

# 资产回看报销

`/expense` 和 `/cr` 走的是同一条路：

| | 报销 | 研发审查 |
|--|------|----------|
| 工序 | Skill 步骤 | `/cr` 检查单 |
| 手脚 | wecom 等 | gitlab 等 |
| 验收 | 读回字段/总额 | CI + 评论门禁 |
| 分发 | 规则在资产里 | kit / 仓库 |

→ **资产章只记一件事：工序 + 手脚 + 验收 + 分发。**
