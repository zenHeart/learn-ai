# 从报销单开始

> 月底，需要处理 **AI 中转站** 的报销

<v-click>

**我要做的事情**

</v-click>

<v-clicks>

1. **收集** 同事发来的报销单据（截图 / 发票）
2. **整理** 按 **类型**、**同事名称** 归类命名
3. **礼品卡打包** 将礼品卡类消费截图打成 **ZIP**，交给三方去开发票
4. **汇总表** 全部票据齐了之后，做一张表方便 **财务复核**
5. **企微提交** 在企业微信上提交报销单
6. **纸质闭环** 审批通过后：打印发票 → 填纸质报销单 → **交财务**

</v-clicks>

# 时间花在哪

<v-clicks>

1. **看发票** — 人工看图/PDF，填金额、渠道、归属人
2. **分组与命名** — 按同事、类型、渠道归类重命名
3. **打包压缩** — 礼品卡截图筛出来、打 ZIP、金额合计还要对上，发给三方开发票

# 有了 AI  如何优化报销流程

| 报销环节 | AI 解法 |
|------|----------|
| 看发票 | OCR / 多模态大模型 (MLLM) 支持识别图片, 提取金额，识别渠道  |
| 分组与命名 | Agent 处理识别后的图片， 按照 `<人员>-<渠道>-<金额>-<标签>.<扩展名>`  命名| 
| 打包压缩 | 打包 `<渠道>` 为礼品卡资源 |
| 撰写表格 | 利用 `nn-ai mcp-wecom-doc` 创建财务审查的表格 |

然后固化上述流程沉淀为 `expense` 技能，后续只需要把图片粘贴到一个文件夹运行 `/expense` 自动完成上述动作。

# 人 × Agent 协作模式

先定义协作协议，再选择执行模式；把一次协作沉淀为可复用系统。

<HumanAgentSystem />

<!--
口播（≈65s）：
「报销举例，研发/运营同一思路。

先立协议：人定报销规则和验收标准——Outcome 是『报销单据齐了、金额对上』，Context 是月份/渠道，
Constraints 是别超预算，Authority 是能不能自动打包发企微表，Evidence 是读回一致，
Stop/Escalate 是票看不清就停下转人；Agent 照协议推理、行动、汇总证据回来。

四种模式不是『越往后越先进』，是按任务特征挑：
对话式协作——目标还没说清，票看不清就来回问，这是 Chat；
目标式委派——结果明确但路径要探索，定好『所有票分类完、汇总表金额对上』，Agent 自己计划执行到校验完；
流程式编排——报销六步里 1–4 已经高频稳定，固化成 `expense` Skill 直接复用；
多 Agent 编排——票量大、能拆开的时候，礼品卡和普通发票分给不同 Agent 并行处理，最后汇总核对。
选哪种看任务的不确定性、频率、风险和能不能拆，不是升级打怪。

复利闭环：报销读回不一致时，留痕、评测、定位偏差，人复盘确认后写回规则或 Skill，
下个月这条流程更稳、更快、更少人管——没写回资产，下次还是从头来。」
