# 从报销单开始

> 月底，需要处理 **AI 中转站** 的报销

<v-click>

**我要做的事情**

</v-click>

<v-clicks>

1. **收集** 同事发来的报销单据（截图 / 发票）
2. **整理** 按 **类型**、**同事名称** 归类命名
3. **礼品卡打包** 将礼品卡类消费截图打成 **ZIP**，交给三方去开发票
4. **汇总表** 全部票据齐了之后，做一张表方便 **财务复核**
5. **企微提交** 在企业微信上提交报销单
6. **纸质闭环** 审批通过后：打印发票 → 填纸质报销单 → **交财务**

</v-clicks>

# 时间花在哪

<v-clicks>

1. **看发票** — 人工看图/PDF，填金额、渠道、归属人
2. **分组与命名** — 按同事、类型、渠道归类重命名
3. **打包压缩** — 礼品卡截图筛出来、打 ZIP、金额合计还要对上，发给三方开发票

# 有了 AI  如何优化报销流程

| 报销环节 | AI 解法 |
|------|----------|
| 看发票 | OCR / 多模态大模型 (MLLM) 支持识别图片  |
| 分组与命名 | Agent 处理识别后的图片， 按照 `<人员>-<渠道>-<金额>-<标签>.<扩展名>`  命名| 
| 打包压缩 | 打包 `<渠道>` 为礼品卡资源 |
| 撰写表格 | 利用 `nn-ai mcp-wecom-doc` 创建财务审查的表格 |

然后固化上述流程沉淀为 `expense` 技能，后续只需要把图片粘贴到一个文件夹运行 `/expense` 自动完成上述动作

# 人与 Agent：擅长什么 · 如何扩展 · 怎么配合

目的不是比谁赢，而是：**先看清能力边界 → 才知道什么适合人、什么适合 Agent、怎么一起干活、各自怎么变强。**  
报销只是例子；研发 / 运营同一思路。

### ① 各擅长什么（什么适合谁）

| | **人** | **Agent** |
|--|--------|-----------|
| **更擅长** | 定目标和规则；拿不准时拍板；担责任；走线下 | 批量处理信息（如读图）；按规则重复做；连内部系统；按标准自检 |
| **报销上** | 收单据、定命名/替票规则、处理问不清的、审批、打印交财务 | 整理命名、礼品卡打 ZIP、做汇总表、写企微表并核对 |
| **不适合硬扛** | 每月人肉一张张抄数、对总额 | 替人审批；猜不清的票；纸质交财务 |

### ② 各自如何扩展（怎么变强）

| **人怎么扩展** | **Agent 怎么扩展** |
|----------------|-------------------|
| 更懂业务；把经验**写清楚**（规则、验收） | 更强模型 / 读图能力 |
| 用工具、检查清单、带人 | **加手脚**（脚本、MCP，如企微） |
| 复盘失败，改标准 | **加工序**（Skill，如 `/expense`） |
| 报销：经验 → 写进 Skill，人从「抄票」升级到「定标准 + 拍板」 | 报销：读图 + 脚本 + 企微接入 + 预检门禁 → 执行面变宽 |

### ③ 协作模式（怎么打配合）

| 模式 | 含义 | 报销上 |
|------|------|--------|
| **人定，Agent 做** | 人写清输入/步骤/输出/怎样算完，Agent 执行 | 规则进 Skill → 跑 `/expense` |
| **问不清交还人** | Agent 不瞎猜，标出来等人定 | 票看不清 → unknown |
| **关键节点人在环** | 审批、对外口径、线下交接仍是人 | 步骤 5–6 |
| **失败即停** | 对不上就不算成功，不假装做完 | 预检 / 读回不一致 → 停 |

<div v-click class="mt-3 p-3 bg-orange-50 border border-orange-200 rounded text-sm">

**一句话：** 人负责 **定规则、拍板、担责、走线下**；Agent 负责 **重复执行 + 接系统**。  
人变强靠把经验写清楚；Agent 变强靠工具和 Skill。配合 = 交接清楚 + 例外交还 + 人守最后一公里。

</div>
