# 实操结构

**路径 A** — 报销工作流：讲清「如何沉淀」  
**路径 B** — 研发闭环：讲清「如何用 nn-ai」

两条路径同一套飞轮，映射不同业务。

::: tip 时间盒
单路径演示建议 **≤5 分钟**；超时切录屏，保留「验收门禁」镜头。
:::

# 路径 A · 工作流定义（对齐冷开场 1–6）

| 完整流程 | 自动化边界 |
|----------|------------|
| 1 收集同事单据 | 人：放进月份目录 |
| 2 按类型/同事整理 | **`/expense`** |
| 3 礼品卡打 ZIP 交三方开票 | **`/expense`** |
| 4 汇总表供财务复核 | **`/expense`** → `expense.md`（+ 企微表） |
| 5 企微提交报销单 | 部分：智能表写入；**审批决策人守** |
| 6 打印 + 纸质单交财务 | **人守** |

| 项 | 内容 |
|----|------|
| **输入** | 月份目录内支付截图、发票 |
| **输出** | 规范命名、礼品卡 ZIP、`expense.md`、（可选）企微月表 |
| **验收** | 预检失败即停；企微写入则 **读回** 字段/行数/总额一致 |
| **人只做** | 放原始凭证 + 确认 unknown + 步骤 5–6 决策与纸质 |
| **触发** | `/expense` 或 `/expense 2026-08` |

**能力组合：** 视觉读图 + Skill 工序 + 本地脚本 +（可选）wecom MCP + 双遍读图/SHA 门禁。

# 路径 A · 演示节拍（≤5 min）

| 分钟 | 动作 | 观众应看到 |
|------|------|------------|
| **0:00–1:00** | 打开「脏」月份目录 | 命名乱、标准不一 |

# 路径 A · 飞轮标注

| 飞轮 | 落点 |
|------|------|
| **① 识别** | 六步里 1–4 人肉读票/分组/ZIP/写表 |
| **② 补齐** | 视图读图 + 工序 Skill + 脚本；（可选）企微手脚 |
| **③ MVP** | `/expense`：scan → 识别 → seal → finalize →（读回） |
| **④ 迭代** | 替票规则、双遍金额、权限不进 skill |
| **复利** | 人放文件 + 守 5–6；标准在 `expense` Skill |

---

# 路径 A · 可迁移结论

1. **高频 + 可验收** 的事务，优先 Skill 化  
2. **成功标准要写成门禁**，不能靠「感觉做完了」  
3. **MCP 解决触达，Skill 解决每次做对**  
4. 非研发场景同样适用：纪要、周报、数据拉数、巡检……

# 路径 B · 研发主链路（nn-ai）

```text
需求 → /spec → 工作台实现 → /cr + CI →（可选）/wiki
Bug  → /bugfix（local 状态机）→ 人确认 → 远程验证 + MR
```

| 步骤 | 能力 | 人在环 |
|------|------|--------|
| 拆解 | /spec · atlassian | 确认范围与优先级 |
| 定位/修复 | `/bugfix` local 状态机（`nn-client-all` 自建） | `LOCAL_READY` 后人确认是否继续交付 |
| 实现 | 工作台 Agent Loop | Review 关键设计 |
| 质量 | /cr · gitlab CI | 合并决策 |
| 沉淀 | /wiki | 对外口径 |

---

# 路径 B · 演示节拍（≤5 min）

| 分钟 | 动作 | 观众应看到 |
|------|------|------------|
| **0:00–1:00** | 一个真实 Bug 入口（禅道链接） | 输入清晰 |
| **1:00–2:30** | `/bugfix` 跑 local 状态机：复现 → 定位 → 修复 → 复核 | 状态门一步步推进，不是一句话变出答案 |
| **2:30–4:00** | 停在 `LOCAL_READY`：读「本地已修复，远程未核验」 | **人工确认点**——继续交付需要人明确说「走」 |
| **4:00–5:00** | 讲清楚 delivery 阶段要做什么（MR、test-assets、CI 报告），但不现场跑 | 门禁在系统里，不靠演示者嘴上说 |

::: tip
不要现场演示到 delivery——推 test-assets、跑远程 CI 依赖真实环境，容易翻车。演示到人工确认点为止，比强行走完更可信。
:::

# 路径 B · 飞轮标注

| 飞轮 | 落点 |
|------|------|
| **① 识别** | 需求理解、CR、上下文搬运成本高 |
| **② 补齐** | 文档/工单 MCP + /spec + /cr 工序；`/bugfix` 复用 `/debug` 技能——工序叠工序 |
| **③ MVP** | 一条需求从拆解到 MR 评论闭环；一个 Bug 从 local 复现到人工确认 |
| **④ 迭代** | 补记忆文件、缩权、失败写回 Skill |
| **复制** | 邻项目同一链路；kit 统一分发 |
