# Agent 有哪些「可扩展能力」

| 能力面 | 含义 | 典型落点（CC / Codex） |
|--------|------|------------------------|
| **记忆** | 每会话自动带上的项目宪法 | `CLAUDE.md` / `AGENTS.md` |
| **手脚** | 触达外部系统的原子能力 | MCP、CLI、内置 tools |
| **工序** | 可复用的 SOP | Skills、Commands（**find-skill 先找现成的、skill-creator 现造**） |
| **护栏** | 工具前后约束 | Hooks、审批、sandbox |
| **并行** | 隔离上下文或角色拆分 | Subagents / Teams / worktree |
| **分发** | 换项目 / 换机器也能直接用 | Plugin / marketplace / **nn-ai** |
| **定时** | 按周期/事件自动触发，不用人起头 | Scheduler / cron routines |

**三问（换工具也适用）：**  
能挂什么工具？能沉淀什么工序？能固化什么记忆？

::: tip
这六层能叠加组合成新资产：Skill 里挂 MCP，Plugin 里打包多个 Skill + MCP——nn-ai 的 kit 就是这么打包分发的。
:::

# 工作流形态：`工作流` 还能再细分

开场报销页三类配合方式——聊天、目标管理、`工作流`——最后这类里还分四种具体形态：

| 形态 | 何时用 | 风险 |
|------|--------|------|
| **固定链 Chaining** | 步骤可预拆 | 步骤设计错误会全链错 |
| **路由 Routing** | 多类入口（需求/Bug） | 分类错则路径错 |
| **生成-评审 Eval** | 有清晰 rubric | rubric 含糊则评审无效 |
| **编排 / 多 Agent** | 真并行、角色必须拆 | 交接不清则更慢更贵 |

**默认主路径：** 定义任务 → 聊天或目标管理先跑通 → 需要时再上这四种；  
**最后**才上多 Agent 编排。

::: tip
生产里多数成功案例是 **workflow（可约束步骤）**，不是一上来全自主 Agent。
:::

# 思维转换：从「完成一次」到「沉淀一条」

| 旧思维 | Agent 时代思维 |
|--------|----------------|
| 这次问完就算 | 下次是否还能零思考复用？ |
| 人记住流程 | 流程写进 Skill / 记忆文件 |
| 结果「看起来对」 | 结果可命令验收 / 读回 / CI |
| 个人秘籍 | 写成能反复调用的资产（Skill / kit） |
| 工具越多越好 | 缺哪一层补哪一层 |

报销那条例子说的也是这件事：  
**输入（凭证）→ 步骤（识别/命名/上传）→ 输出（表+ZIP）→ 验收（读回）**  
= 一条可沉淀工作流。

# 委托启发式：什么交给 Agent

| 适合交给 Agent | 人要留住 |
|----------------|----------|
| **验收成本 ≪ 生成成本** | 高层次设计 / 业务判断 / taste |
| 定义清晰、边界清楚 | 合并、发布、对外口径、合规 |
| 无聊 / 低风险 / 可丢弃试错 | 「看起来聪明」但危险的改动 |
| 信任可渐进（先简单后复杂） | 自己验不了的「黑箱全包」 |

::: tip 像用地图
先用不熟的路 → 再用于熟路优化 → 最后才敢「闭眼跟导航」。  
**Trust but verify**，边界随能力重谈。
:::

# 识别工作流：四个问题

识别之前往往还有一步：**先把环境打通**——机器和机器、机器和内部系统先接起来，才有得识别。

1. **是否高频？** 每周/每月重复才值得沉淀  
2. **I/O 是否清晰？** 说不清输入输出，Agent 只能猜  
3. **验收是否客观？** 能测试、能读回、能 diff 才稳  
4. **缺的是手脚还是工序？**  
   - 碰不到系统 → CLI/API/MCP  
   - 每次重复长说明 → Skill  
   - 结果飘 → 验收 + Loop  
   - 只有你会 → 分发（nn-ai / 记忆文件）

# 一天怎么工作（行为剧本）

```text
早上   Plan：一条目标 + Done when（验收）
工作中  1 主 Agent 执行  +（可选）并行调研 / 子任务
门禁   测试 · /cr · 读回 · CI —— 不过门禁不算完
结束   10 分钟：失败写回记忆文件或 Skill 草稿
```

| 角色感 | 含义 |
|--------|------|
| **你是 captain** | 定目标、派工、验收，不是更好 prompt 的打字员 |
| **并行** | 真瓶颈再拆；默认先单线程跑通 |
| **Skill 按需** | 工序加载，不把百科全书塞进每次对话 |

# 这样不会有复利（反模式）

::left::

### 常见翻车

1. **没验收就放权** → 空转 / 假完成  
2. **没定义就上多 Agent** → 更贵更慢  
3. **100 个聊天标签** vs **0 个 Skill**  
4. **私接脚本绕过 nn-ai** → 换台机器自己都找不回来  
5. **「看起来对」当 Done**  

::right::

### 对照做法

1. **无验收 = 无复利**  
2. 先单 Agent + Done when  
3. 重复第二次就沉淀  
4. 内网手脚统一走 kit  
5. 命令 / 读回 / CI 门禁  

<div class="mt-4 p-3 bg-red-50 border border-red-200 rounded text-sm">

**记住：** 复杂度只在**证明有收益**后增加。

</div>

# 本章小结：方法

<v-clicks>

1. **自下而上**：定义 → 能力面 → 协作形态 → 沉淀 → 迭代  
2. **委托**：可验收、低风险、定义清；人守 taste 与风险  
3. **默认路径**：单 Agent + 验收；慎上多 Agent  
4. **反模式**：没验收 / 没定义 / 只会话不分发 = 无复利  

</v-clicks>
