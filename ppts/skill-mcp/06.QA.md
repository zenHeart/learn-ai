### **Q1：我写的 Skill，AI 经常不触发或乱触发？**

A: **description 是写给「模型读」的，不是堆关键词。**

<div class="mt-4 space-y-3 text-sm">

1. 写清 **what + when**（第三人称）：做什么 + 什么场景用 + 1-2 个高区分度名词
2. 两个 Skill 撞车 → 加限定词区分（"**单元**测试" vs "**端到端**测试"）
3. 高危操作 → `disable-model-invocation: true`，只许 `/name` 显式触发
4. 写完用两句话 **dry-run**：一句该命中、一句不该命中

</div>

::right::

### **Q2：为什么把内部系统包成 MCP，不直接写脚本？**

A: **一次性脚本确实更快；要复用就是降维打击。**

<div class="mt-4 space-y-3 text-sm">

1. **复用**：写一次 `@nn/mcp-zentao`，Claude / Cursor / Codex 全能用，换工具不重写
2. **密钥隔离**：账号封在 Server 端，不喂给模型（直接写脚本 = 把生产密码交给 AI）
3. **治理**：统一鉴权 / 限流 / audit / 版本
4. 反过来：纯一次性、只你自己用 → 别包，写函数更快

</div>

### **Q3：装了一堆 Skill / MCP，AI 会不会变慢、变笨？**

A: **会 —— 清单常驻 context，越多越稀释判断。**

<div class="mt-4 space-y-3 text-sm">

1. 每个 Skill 的 `name+description`、每个 MCP 的工具清单，**启动就常驻**，挤占预算
2. 太多无关条目 → 模型每轮都要在噪音里挑 → 选错 / 变慢
3. 对策：**按需启用，别全家桶**；description 写准让模型好挑
4. 工具多时用 **deferred / ToolSearch** 按需曝光，不必全量塞进主 prompt

</div>

::right::

### **Q4：团队怎么灰度上线、写错了怎么回滚？** <span class="text-xs text-slate-400 font-normal">🏢 企业级</span>

A: **Git 管理 + 版本号 + 分阶段下发，回滚 30 秒。**

<div class="mt-4 space-y-3 text-sm">

1. 团队资产放专用仓 / `packages/`，版本走 SemVer，内部 npm 分发
2. 灰度：5% 试用 → 收反馈 → 30% → 全量
3. 写错 description 导致疯狂误触发？`git revert` + 重启会话，30 秒回滚
4. 远程 MCP：集中部署 + OAuth + `Origin` 校验 + audit log（细节见附录）

</div>
