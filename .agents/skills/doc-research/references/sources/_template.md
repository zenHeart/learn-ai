# 高质量数据源清单模板

> 方法论 + 条目格式，本身不产出数据。清单写进读者可见的 cheatsheet「高质量信息源」，不要再拆一个 `sources.md`。只收录亲自打开核实过的条目；不确定的放「待核实」。

## 怎么发现（先读再搜）

### 1. 先画官方属性地图

产品几乎从不只有一个官方域名。主文档站之外通常还有 Blog、API 站、Cookbook、Courses、GitHub org、社交账号。搜索引擎对站内导航收录差，纯搜索会漏官方自己的图。

1. 从主文档域名读**首页 / 页脚 / Resources**
2. 每发现新官方域名就重复，直到不再冒出新域名
3. 走完官方地图再搜第三方

### 2. 社交账号

优先用能读该平台实时数据的搜索（含无头 CLI，见 [`headless-search.md`](../headless-search.md)）。普通网页搜索摘要不够判断认证状态和近期互动。

核实：账号 URL 真实存在；官方或员工亲自链过；收录时写「整理自某次搜索」，不要把粉丝数写进长期文档。调不通就放「待核实」。

## 条目格式

```
- **[名称](https://example.com)** — 一句话说明为什么权威
  - 建议访问方式：官方页阅读器 / 网页搜索 / 源码搜索 / 需人工打开
  - 最后核实：YYYY-MM-DD
```

超过 3–6 个月没核实的，用之前先确认链接还活着。

## 分类

- 官方文档（主站 + 独立 API/平台站，写清受众）
- 官方 Cookbook / 示例 / Courses
- 官方与核心团队社交账号（公司 / 产品 / 负责人 / 核心开发者，写清怎么核实身份）
- 核心维护者 Blog
- GitHub 高质量仓库（官方仓写清公开了什么）
- Awesome List（带 owner，看最近 commit）
- 三方高质量 Blog / 社区（中文尤其要辨搬运）
- 待核实（名称 + URL + 为什么怀疑 + 待确认点）
