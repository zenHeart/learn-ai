# 论断分类与核验标准（Claim Taxonomy）

事实审计第一步是把全文断言分类登记。每类论断有不同的伪造风险模式和核验要求。

## 1. 人物（Person）

- **覆盖**：姓名拼写、职务/头衔、履历时间线、所属机构、公开演讲/署名文章、获奖。
- **高危模式**：同名张冠李戴；头衔随时间变化（「CTO」在何时是 CTO）；把公司行为归于个人。
- **核验要求**：一手来源优先——个人主页、公司官网 leadership 页、演讲视频/官方 transcript、领英仅作旁证。至少两个独立来源。

## 2. 事件（Event）

- **覆盖**：发布/停运/收购/融资、版本号与日期、事故与恢复、监管动作、因果链（A 导致 B）。
- **高危模式**：
  - **媒体时间 ≠ 事件时间**（铁律 2）：转载日期晚于发生日；必须先找一手来源确认真实发生时间。
  - 因果链省略中间环节，把相关性写成因果。
  - 时区错位导致的「提前一天/晚一天」。
- **核验要求**：官方博客 / GitHub release / 监管公告 / 事故报告（postmortem）为一手来源；事件日期以一手来源为准，媒体仅作佐证。

## 3. 数据（Data）

- **覆盖**：精确数字、百分比、排名、成本/价格、性能指标（benchmark）、市场规模、用户量。
- **高危模式**：精确到小数点的数字无出处；把估算写成测量值；benchmark 脱离测试条件（硬件、版本、数据集）。
- **核验要求**：精确数字必须指向原始数据集/财报/论文/官方公告，并注明 as of 日期；benchmark 必须带测试条件；查无实据者降级为可核验的近似表述或删除（铁律 1）。

## 4. 直接引语（Direct Quote）

- **覆盖**：引号内逐字内容、标语口号、公开承诺、访谈原话。
- **高危模式**：意译被写成逐字 quote；拼接两段话；翻译回译后冒充原文。
- **核验要求**：**逐字可验**——找到含该确切字符串的原始页面/视频/文档；找不到一律删除或改为无引号的转述并注明来源。这是所有类型中标准最严的。

## 5. 源码级断言（Code-level，技术书专用）

- **覆盖**：事件名、环境变量、CLI 参数、配置键、文件路径、函数/类名、默认值、行为描述。
- **核验要求**：对目标仓库当前内容分支 grep 逐个验证；版本漂移的一律更新为当前真实值并写入勘误。

## 引用格式规范

每章参考资料条目：

```markdown
- [标题（来源机构，YYYY-MM-DD）]（URL） — 支撑论断一句话
```

正文内联引用：

```markdown
[Source: 来源机构 — 数据集/文档名, as of YYYY-MM-DD]
```

- 引用优先指向一手来源；转引必须标明（「据 X 转引」）。
- 一个段落混合多个来源时，分别引用，不得合并到段末。
- 禁止虚构来源名、文档标题或日期；只能用核验时真实返回的元数据。

## 勘误节格式

```markdown
### 勘误（vX.Y，YYYY-MM-DD）

| # | 位置 | 原断言 | 修正 | 证据 |
|---|------|--------|------|------|
| 1 | 第N章 N.m | 「……」 | 「……」 | [来源]（URL） |
```

- 自我纠错（审计者改错又改回）同样登记，注明「自我纠错」。
- 勘误跨版本累积归档，不得删除历史勘误。
