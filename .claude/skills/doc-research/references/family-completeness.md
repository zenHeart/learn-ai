# 产品家族完备

> 回答「官方有哪些产品」，不是「教程有哪些章节」。排轴 A/B 之前必须先做完。排序规则在 [`documentation-architecture.md`](./documentation-architecture.md)。

## 硬规则

**官方文档一级导航里的每一个产品 / 入口，必须出现在本站该工具的家族图（`index.md` 决策树）里。**

密度只决定形态，不能把一级产品从地图上抹掉：

| 官方密度 | 本站形态 |
|----------|----------|
| 独立职责 + 足够操作步骤 | 独立 Tutorial 页 + 侧栏 |
| 官方有页，但对目标读者偏薄 | index / cheatsheet **一行** + 官方链接；写明「不拆页」 |
| 不是产品（计划、营销栏目、宠物彩蛋） | 最多 index 一行，禁止教程 |

「不要为凑文件数硬写」禁止的是**虚构产品**，不是禁止收录官方一级入口。

## Retrieve 时怎么列清单

1. 打开官方 docs 首页 / `llms.txt` / 侧栏「产品 / Available on / 一级分类」
2. 列出全部一级项（名称 + 官方 URL）
3. 对照本站 `index.md` 和侧栏：每项标 `独立页` / `地图一行` / **缺失**
4. **缺失 = P0**，先补地图或立页，再写技巧

只扫「安装 / CLI / Settings」教程树、不扫产品家族，会漏掉同品牌的兄弟产品。

## 易撞名

同一品牌里两个东西共用词根时，index 和 glossary 必须写 **「不是什么」**：

- 可执行文件名 ≠ 产品营销名
- 聊天里的某种 Mode ≠ 同名 CLI 产品
- 订阅权益清单里的名字 ≠ 已经停服的旧入口

两份官方页对同一事实打架时：写清以哪份为准，另一份标过时。禁止各写各的，也不要用「通常」抹平。

## 踩过的错

- 只写编码主线，把官方一级的创意 / 桌面 / 托管产品当成「不相关」删掉
- 用「轴 B 相关度低」当理由从家族图消失——轴 B 只决定往后排，不决定删掉
- 订阅表里已经出现某个产品的额度，却没有产品页、也没有决策树节点
