# 学习路径

先回答一件事：**你现在最痛的是哪一句？**

1. 「写代码太慢，助手在那不会用」→ 路径 1  
2. 「要把模型接到自己的产品里」→ 路径 2  
3. 「功能能跑，但不敢上线、算不清成本」→ 路径 3  

三条路是**累计**的，不是三个平行专题。默认 1 → 2 → 3。已经每天在用编码助手的人，可以从 2 进。

**不是**产品说明书（去 [产品](/zh/products/)），也不是模型内部怎么算（去 [Learn LLM](https://llm.zenheart.site/)）。

## 三条路，按阅读顺序

### 1. 使用 AI 工具

**问题**：还在手写样板、自己翻文档、调试耗一下午。  
**做完能干什么**：在编辑器 / 终端里指挥 Cursor、Copilot、Claude、Gemini，让日常开发先快起来。  
**下一步**：有了手感，再把模型接到产品里。

**[开始路径 1](/zh/paths/productivity)**

### 2. 添加 AI 功能

**问题**：助手会用了，但自己的 React / Vue 应用里还没有聊天、搜索、补全。  
**做完能干什么**：调 API、做流式 UI、上 RAG 搜索。  
**前提**：路径 1 的工具手感；会 TypeScript。

**[开始路径 2](/zh/paths/integration)**

### 3. 构建 AI 产品

**问题**：Demo 能秀，生产环境超时、账单炸、没有评估。  
**做完能干什么**：部署、限流、监控、算成本、写评估。  
**前提**：路径 2 里至少做过一个能跑的功能。

**[开始路径 3](/zh/paths/mastery)**

## 怎么选（一张表）

| 你现在的情况 | 走哪条 |
|---|---|
| 几乎没认真用过编码助手 | 路径 1 |
| 每天在用助手，要给现有应用加能力 | 路径 2 |
| 已经接过 API / RAG，要上线 | 路径 3 |
| 产品经理，只想判断能力边界 | 先读路径 1 的决策部分，再看 [企业实践](/zh/practice/) |

## 建议节奏

- 路径 1：1–2 周，每天在真实仓库里用  
- 路径 2：2–4 周，做出一个流式功能  
- 路径 3：按上线清单走，不设死周数  

机制（为什么 prompt 这样写、RAG 为什么能减轻幻觉）链到 [技术](/zh/tech/) 和 Learn LLM，本栏只负责「按什么顺序做」。
